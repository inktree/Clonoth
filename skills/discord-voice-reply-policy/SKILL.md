# Discord 音频消息与 TTS 回复规则

Discord 适配器已经接入音频输入和语音输出。该能力不是模型需要调用的工具，也不需要搜索接口或自行调用 Mimo。

## 输入

用户发送 Discord 音频消息或音频文件后，适配器会先调用 Mimo ASR 转写，再把转写文本交给模型。模型只需按照转写内容回答，不要尝试处理底层音频文件，除非用户明确要求检查文件本身。

## 输出

需要发送语音时，将适合朗读的自然语言放在 `<tts>` 和 `</tts>` 之间。Discord 适配器会提取这些片段，调用已经接好的 Mimo TTS，并发送音频附件。

示例：

```text
文字部分应提供完整回答。

<tts>（温柔）这里是适合朗读的附加语音内容。</tts>
```

必须遵守：

1. 不要搜索 TTS 工具，不要寻找 Mimo 端点，不要调用网页搜索来确认这项既有能力。
2. 不要声称自己不能发送语音。只需输出 `<tts>` 片段，由 Discord 适配器完成合成和发送。
3. 不要发送纯 TTS。正常文字部分必须包含完整回复，TTS 是附加语音版本。
4. `<tts>` 内只放适合直接朗读的自然语言。代码、日志、表格、长列表、文件路径和工具结果不要放入其中。
5. 可以输出多个 `<tts>` 片段；适配器会依次处理。
6. 可以少量使用 Mimo 支持的整体风格标签和音频标签，例如 `（温柔）`、`（认真）`、`[轻笑]`、`[深呼吸]`。
7. 不要主动使用唱歌标签。只有用户明确要求唱歌或测试唱歌模式时才使用。
8. 用户通过语音输入时，优先附加简短语音回复。用户通过文字输入时，仅在用户明确要求语音或确实适合时附加。
9. 群聊中保持克制，避免无必要的长语音。
10. `<tts>` 片段会从 Discord 的显示正文中移除，因此文字正文不得依赖该片段才能完整表达答案。

## 故障判断

如果已经正确输出 `<tts>`，但 Discord 没有出现音频附件，这是适配器、Supervisor TTS 请求或附件发送链路的问题。不要反复搜索所谓语音工具，也不要仅靠重复同一标签判断成功。应检查 Discord Bot 日志和 Supervisor 音频接口错误。
