# BotTTS 长期记忆规范

当前 BotTTS 运行在 Clonoth 的长期记忆系统之上。

记忆系统已经启用：

- 自动记忆提取（auto_extract）
- Dream 周期整理（dream）
- keyword 激活
- constant memory
- memory 注入

当前阶段不修改 Clonoth 默认 memory extractor，而是通过本 skill 引导长期记忆逐渐形成稳定的本地开发上下文。

## 当前项目的重要长期事实

以下内容属于重要长期上下文，应在后续工作中保持一致：

1. `Clonoth/` 是当前运行实例与框架层。
2. `BotTTS/` 是当前业务 Bot 项目。
3. BotTTS 的节点、skills、文档和脚本优先维护在 `BotTTS/`。
4. 通过同步脚本把业务配置同步到 Clonoth。
5. 当前阶段重点是本地开发、本地 Web、本地 Shell/TUI。
6. 当前阶段暂不重点处理 QQ、Discord 和公网部署。
7. 除非必要，不要大规模修改 Clonoth 框架源码。

## 什么信息值得进入长期记忆

在 BotTTS 当前阶段，以下信息通常值得保存：

### 项目结构

例如：

- 哪个目录负责什么。
- 为什么采用 BotTTS / Clonoth 分层。
- 哪些目录是业务层。
- 哪些目录属于框架层。

### 本地工作流

例如：

- 如何同步 nodes 与 skills。
- 如何启动本地环境。
- 当前使用哪些脚本。
- 当前默认入口节点。

### 部署与运行决策

例如：

- 为什么暂不接入 QQ。
- 为什么优先本地开发。
- 为什么使用复制同步而不是软链接。
- 为什么不直接污染 Clonoth。

### 长期稳定偏好

例如：

- 默认使用 PowerShell。
- 默认使用中文。
- 优先最小化修改。
- 本地开发优先。

## 什么不应该进入长期记忆

以下内容通常不值得保存：

- 临时调试日志。
- 一次性的报错输出。
- 短期实验步骤。
- 已经失效的临时命令。
- 可直接从代码重新获得的信息。
- 大段代码本身。

## 使用记忆时的原则

- 优先把记忆当作长期项目上下文，而不是聊天记录。
- 记忆应帮助维持项目一致性。
- 如果记忆与当前文件实际内容冲突，以实际文件为准。
- 不要把已经过时的工作流继续当成当前规范。

## 当前阶段的目标

让 BotTTS 逐渐积累：

- 本地开发知识。
- 项目结构知识。
- 部署工作流。
- 常见故障处理。
- 长期设计决策。

而不是社交型群聊记忆。
